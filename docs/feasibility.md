# Native feasibility

Verified locally on 2026-10-12, macOS arm64, Node 24.21.0; Claude Code 2.1.280. The native executable was a Mach-O arm64 distribution signed by Anthropic PBC, team `Q6L2SF6YDW`, identifier `com.anthropic.claude-code`; code signature verification passed. Tested binary SHA-256: `387a5c5dcdbb815085edf0baf79591f9d8894efe922bceaf3d75b1b08055229d`. The binary is separately installed and is never bundled.

[Official skills](https://code.claude.com/docs/en/skills), [CLI reference](https://code.claude.com/docs/en/cli-reference), [environment variables](https://code.claude.com/docs/en/env-vars), [authentication](https://code.claude.com/docs/en/authentication), [settings](https://code.claude.com/docs/en/settings) and [programmatic/bare mode](https://code.claude.com/docs/en/headless) were checked with Context7 and primary documentation. Installed `--help` was checked separately. Current docs contain features newer than 2.1.280; support is based on actual pinned-build measurements, not the whole latest documentation.

The prototype used an owned temporary git project/config/session, a UUID source marker, an OS-selected loopback port, an environment allowlist and a synthetic API key. `child_process.spawn` used an absolute executable, argv array and `shell:false`. The prompt was `/parcel-probe` with native arguments; the harness did not inline the body. The server returned Messages SSE, then one controlled native Read and a terminating response. Own selected-config and unselected-profile canaries were absent from actual requests in the final isolation experiment. Raw/vendor request content was not retained as public evidence.

1. `--bare --restricted --add-dir` completed native Read, but did **not** load the body. This attempt failed the target-loader gate; restricted mode was rejected.
2. `--bare --add-dir` loaded the actual project skill. An intentionally placed ancestor `CLAUDE.md` also appeared through explicit additional-directory discovery. The adapter therefore creates a clean temp ancestry, refuses unexpected ancestor customizations and never adds a user's project directory. This is a measured limitation, not universal instruction suppression.
3. With only Read exposed when needed, isolated synthetic config canaries excluded, documented bare authentication and no inherited credentials, three fresh runs completed. The first request contained the native skill body. Reference text was absent first, then appeared in the next request's tool_result with the same mock-issued and native-executed ID. The checks were stable. Seven arguments rewrote the formula identically in every run.

[Minimal original synthetic proof](feasibility-proof.json) preserves owned fragments, IDs and outcomes without headers/system text. Its prototype predates the final tool; the release's final-commit evidence and installed-package consumers are separate acceptance gates. [SHA-pinned adapter manifest](https://github.com/mikonyaa/skillparcel/blob/a6acb183ba25675b49d8e3be19ae87563365be4c/src/adapters/claude-code/manifest.ts) defines the narrow coverage.

`CLAUDE_CONFIG_DIR` is documented to scope settings/history/plugins and credential storage, including the macOS Keychain entry identity. Bare mode additionally avoids OAuth/Keychain reads in the tested invocation. The adapter checks for managed file/preference presence and refuses such environments; settings-source flags alone do not remove managed policy. It does not inspect or change personal credential files, account settings or Keychain. It applies documented nonessential-traffic/updater/telemetry opt-outs, binds model requests to its inert loopback provider, and supplies no real-provider credential or fallback. **Strict OS egress confinement was not established.** No global security settings or other sessions were changed.
